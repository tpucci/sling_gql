Every request — batched queries and mutations alike — goes through a single
function:

```dart
typedef Transport = Future<http.Response> Function(http.Request request);
```

By default the client sends the request with its `http.Client`. Pass your own
`transport` to intercept it. The request you receive is a finalized `POST` with
`content-type: application/json` and the client's static `headers` already
applied; you can mutate its headers before sending.

```dart
final client = SlingClient<Query>(
  endpoint: Uri.parse('https://api.example.com/graphql'),
  schema: slingSchema,
  headers: const {'x-app-version': '1.2.0'}, // static, applied before transport
  transport: (request) async {
    request.headers['authorization'] = 'Bearer ${await auth.token()}';
    return http.Response.fromStream(await http.Client().send(request));
  },
);
```

<Aside type="note">
There is deliberately no link chain. Most apps need one function; compose it
yourself with ordinary Dart. If you already use `gql_link`, hand your chain
over as that one function — see [gql_link](#gql_link) below.
</Aside>

## Recipes

Keep one `http.Client` around instead of creating one per request:

```dart
final _http = http.Client();
Future<http.Response> send(http.Request r) async =>
    http.Response.fromStream(await _http.send(r));
```

### Timeout

```dart
transport: (request) => send(request).timeout(const Duration(seconds: 10)),
```

A `TimeoutException` surfaces as `QueryState.error` for every scope in the
batch (sticky until `refetch()`, see
[Loading states & errors](/sling_gql/guides/loading-and-errors/)).

### Retry

An `http.Request` can be sent once, so copy it before each attempt:

```dart
http.Request copy(http.Request r) => http.Request(r.method, r.url)
  ..headers.addAll(r.headers)
  ..bodyBytes = r.bodyBytes;

transport: (request) async {
  for (var attempt = 0;; attempt++) {
    final res = await send(copy(request));
    if (res.statusCode < 500 || attempt == 2) return res;
    await Future.delayed(Duration(milliseconds: 200 * (1 << attempt)));
  }
},
```

Retry inside the transport is invisible to widgets: the scope only sees the
final response.

### Token refresh on 401

```dart
transport: (request) async {
  request.headers['authorization'] = 'Bearer ${auth.current}';
  final res = await send(copy(request));
  if (res.statusCode != 401) return res;
  await auth.refresh();
  request.headers['authorization'] = 'Bearer ${auth.current}';
  return send(copy(request));
},
```

### Logging

`onOperation` already reports every printed document; use the transport when
you want status codes and timing too:

```dart
transport: (request) async {
  final sw = Stopwatch()..start();
  final res = await send(request);
  log('${res.statusCode} ${sw.elapsedMilliseconds}ms ${request.body.length}B');
  return res;
},
```

## What the client does with the response

- `statusCode >= 400` → `SlingException('HTTP <code>')` for the whole batch.
- A JSON body without `data` → `SlingException` with the first GraphQL error.
- `errors` alongside `data` → the errored paths are pruned before caching and
  the error is attached to the scopes that asked for them (see
  [Loading states & errors](/sling_gql/guides/loading-and-errors/)).

## gql_link

Already have a [`gql_link`](https://pub.dev/packages/gql_link) chain — an auth
link, a retry link, persisted queries, a websocket link? `sling_gql_link`
turns it into the client's `transport` (and `subscriptionTransport`). The
runtime stays `http`-only; `gql`, `gql_exec`, `gql_link` and `gql_http_link`
are that package's dependencies.

```sh
flutter pub add sling_gql_link gql_link gql_http_link
```

```dart
import 'package:gql_http_link/gql_http_link.dart';
import 'package:gql_link/gql_link.dart';
import 'package:sling_gql_link/sling_gql_link.dart';

final authLink = Link.function(
  (request, [forward]) => forward!(
    request.updateContextEntry<HttpLinkHeaders>(
      (headers) => HttpLinkHeaders(
        headers: {...?headers?.headers, 'authorization': 'Bearer ${auth.current}'},
      ),
    ),
  ),
);

final link = Link.from([authLink, retryLink, HttpLink(endpoint)]);

final client = SlingClient<Query>(
  endpoint: Uri.parse(endpoint), // nominal: the terminating link sends
  schema: slingSchema,
  headers: const {'x-app-version': '1.2.0'}, // arrive as HttpLinkHeaders
  transport: linkTransport(link),
);
```

**Going in**, each batched document is parsed into the `Request`'s
`DocumentNode` (so links that hash or rewrite the document — persisted
queries — work on it), with its `variables`; sling_gql's documents are
anonymous, so `operationName` is `null`. The client's `headers` are in the
context as `HttpLinkHeaders`; `content-type` and `accept` are left to the
terminating link.

**Coming back**, the first `Response` of the link's stream is the result:
`data`, `errors` (message, locations, path, extensions) and `extensions` are
handled exactly as over HTTP — partial errors pruned before caching and
reported on the scope, `data: null` a `SlingException`. A `LinkException`
becomes a `SlingLinkException`, the `SlingException` the widgets already
show:

| Link exception | `message` | `statusCode` |
| --- | --- | --- |
| `HttpLinkServerException` (status `>= 300`) | `HTTP <code>`, the body's errors in `graphqlErrors` | the status |
| `HttpLinkParserException` with status `>= 300` (a proxy's 502 page, an empty 401) | `HTTP <code>` | the status |
| `ServerException` of a failed connection | the cause's message | `null` |
| any other `LinkException` | the cause's message | `null` |

`linkException` keeps what the link threw (and its `originalException`).
Anything else a link throws — a `TimeoutException` of your own — surfaces
unchanged, like with the default transport.

<Aside type="caution">
A retry link has to catch the error of `forward(request)`: in an `async*`
link, `yield* forward(request)` *forwards* the error instead of throwing it.
Loop with `await for (final r in forward!(request)) yield r;` inside the
`try`.
</Aside>

### Subscriptions over a link

`linkSubscriptionTransport(link)` maps the link's stream one to one: each
`Response` is an event, the stream completing completes the subscription, a
stream error is a transport failure (which reconnects with `retryAfter`, see
[Subscriptions](/sling_gql/guides/subscriptions/)), and cancelling the
subscription cancels the link's stream. `HttpLink` cannot run subscriptions;
route them to a websocket link:

```dart
final link = Link.split(
  (request) =>
      request.operation.getOperationType() == OperationType.subscription,
  websocketLink,
  Link.from([authLink, HttpLink(endpoint)]),
);

SlingClient<Query>(
  endpoint: Uri.parse(endpoint),
  schema: slingSchema,
  transport: linkTransport(link),
  subscriptionTransport: linkSubscriptionTransport(link),
);
```

Or keep sling_gql's default GraphQL-over-SSE subscriptions and pass only
`transport:`.
