import { Aside, Steps } from '@astrojs/starlight/components';

Each item below is scoped so it can be built and tested against the bundled
[mock API](/sling_gql/tooling/mock-api/), which already exposes the server side of
phases 2 and 3. The detailed, numbered backlog (including DX and performance findings
from the example app) is `TODO.md` at the repository root; this page is the summary.

<Steps>

1. **Normalized cache** — done

   Objects with `__typename` + `id` are stored once, referenced from the tree, and scopes
   are notified per entity field. `launch(id:)` is served from the entity the list wrote.
   See [Caching](/sling_gql/guides/caching/). Left for later: type policies (custom merge
   per field, connection merging) and automatic `gc()`.

2. **Mutations** — done

   `client.mutate((m) => m.toggleFavorite(launchId: id)?.favorite)` and
   `MutationBuilder<Mutation>`, with journaled optimistic writes rolled back on failure. See
   [Mutations](/sling_gql/guides/mutations/). Left for later: write policies for
   create/delete (prepend a ref to a list, `evict` helpers on the accessor), `refetchQueries`
   sugar, and **list membership after a mutation** — e.g. after `toggleFavorite`, the
   `me.favorites` list and `launches(filter: {favorite: true})` should gain or lose the
   launch without a full refetch; that requires write policies that add/remove a `Ref` in a
   cached list.

3. **Subscriptions**

   The mock API serves `launchStatusChanged` and `launchScheduled` over SSE. A
   `SubscriptionBuilder<Subscription>` records a selection once, opens the stream, and
   writes each event into the cache.

4. **Unions and interfaces (`$on`)**

   Generator emits `PetOn get $on` with one getter per possible type; printer emits inline
   fragments `... on Cat { meows }`. Add a union to the mock schema first.

5. **Fine-grained rebuilds** — mostly done

   Scopes now rebuild on `entity.field` intersection instead of root aliases. Remaining:
   list-index granularity for inline lists, and skipping rebuilds when a written value is
   equal to the cached one inside inline objects.

6. **Cache expiry and SWR**

   `maxAge`, `staleWhileRevalidate`, `WeakReference`-held stale entries, soft `refetch()`
   that is a no-op on fresh data.

7. **Developer experience** — in progress

   Done: real Dart `enum`s with an `unknown` value (see
   [Code generation](/sling_gql/tooling/code-generation/)), no setters on key fields or
   connection metadata, and `PaginatedQueryBuilder` (see
   [Pagination](/sling_gql/guides/pagination/)). Next: dev-mode waterfall warning, then the
   in-app overlay attributing each request to the widgets that recorded it; a `pixel`-style
   log line per operation; `flutter_hooks` adapter (`useSlingQuery`).

8. **Transport options**

   `gql_link` adapter for auth headers, retries and persisted queries, without changing
   the runtime's `_post` contract.

</Steps>

## Explicitly not planned

- **SSR hydration.** Not applicable.
- **Lazy / transaction / paginated query variants.** `resolve()` plus widget state cover
  the same ground.

<Aside type="note" title="Contributing">
Every runtime change ships with a test in `packages/sling_gql/test`, and every example
change keeps `example/test/app_test.dart`'s request counts exact. Read `AGENTS.md` at the
repository root before starting.
</Aside>
